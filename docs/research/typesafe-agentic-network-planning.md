# TypeSafe/Jev for intelligent network-planning passes

Research for the Wayfinder ticket [Establish Jev capabilities for intelligent network-planning passes](https://github.com/awjreynolds/agentic-satn-compiler/issues/436).

- Retrieved: 2026-09-19
- Research branch: `research/typesafe-planning-20260919`
- Version basis: current TypeSafe documentation reviewed on 2026-09-19; the Models page identifies the current Jev release as `jev-1.13.0` and `jev-latest` as its moving stable alias ([Models](https://docs.typesafe.ai/models.md)).
- Scope: capability and boundary evidence for compiler mid-end decisions; no production implementation or new benchmark.

## Decision aid

Use Jev as a typed judgment component inside an agentic compiler loop. At the API boundary, Jev evaluates a supplied state and returns constrained answers; it does not run an autonomous loop or execute side effects. A compiler may still let a Jev answer choose the next typed, code-owned action: for example, request a missing evidence package, expand a governed candidate search, or select a candidate for validation. Code then executes that action, builds the next governed state and candidate/action set, and asks the next question. The compiler must preserve evidence and unknowns, check coverage for each request, enforce owner policy and exact topology, and record the authority decision. This extends TypeSafe's documented architecture of code-owned workflow and deterministic work with model-guided sequencing ([System One](https://docs.typesafe.ai/concepts/system-one.md), [How to build](https://docs.typesafe.ai/concepts/how-to-build-with-system-one.md), [function calling](https://docs.typesafe.ai/cookbooks/function_calling.md)).

For the requested “radically more intelligent” compiler, the useful seam is **model-guided, code-executed planning passes**, rather than an API that directly authors or mutates routes. A generative or stronger reasoning model remains an open complementary component for open-ended decomposition, explanation, proposal drafting, or difficult multi-step synthesis; Jev can judge each bounded action and evidence state against compiler-controlled schemas. TypeSafe explicitly says System One is not an agent and does not itself generate code or choose its own next action, while its function-calling pattern shows code dispatching model-selected typed actions and its Jev 1.13 limitations recommend a generative model for generation ([How to build](https://docs.typesafe.ai/concepts/how-to-build-with-system-one.md), [function calling](https://docs.typesafe.ai/cookbooks/function_calling.md), [Jev 1.13 jaggedness](https://docs.typesafe.ai/model-jaggedness/jev-1.13.md)).

## What this means for connection and alignment passes

The strongest supported pattern is a **model-guided, code-executed planning pass**:

1. Deterministic code resolves governed evidence, computes exact geometry/topology facts, and prepares the relevant candidate/action set plus explicit no-match/unknown actions for this step.
2. A structured state names the connection, candidate IDs, claim-specific evidence and owner policy. The question asks one bounded judgment, such as “which supplied candidate best satisfies this policy under these facts?” or “which typed next action is required by this evidence state?”
3. Jev returns a typed label and distribution. Independent questions can assess current usability, evidence sufficiency, intervention need and conflict presence in one request.
4. Deterministic code combines answers, applies hard rules, preserves conflicts and unknowns, and either emits a candidate selection/gap or executes the selected typed action to build the next governed state and candidate set.

This is an architectural implication of the documented interface, not a claim that Jev reasons over a road graph or proves a route. A Choice can only select among options supplied to it; the Choice docs explicitly recommend `other`/`none of the above` when coverage is incomplete ([Choice](https://docs.typesafe.ai/primitives/choice.md)). The pass therefore checks candidate coverage at each request and must never interpret a high-probability label as permission to invent missing geometry. Owner policy remains a governed decision; exact geometry, topology and continuity remain deterministic validation obligations.

For evidence, the claim should be separated from the asset identity: “does this observation support current cycling access?” and “does this candidate have continuous geometry?” are different questions with different authorities. The citation-check cookbook demonstrates the same separation: ordinary code first checks whether a quote exists, then a Choice judges whether the surrounding section supports, contradicts or says nothing about a claim ([citation check](https://docs.typesafe.ai/cookbooks/citation_check.md)).

## Current synthetic observation

The completed local smoke artifacts at the main repository's `build/typesafe-experiments/2026-09-19-smoke/` contain three live synthetic cases, each batching Choice, Noul and Score questions. All three returned HTTP 200 from the documented endpoint with actual model `jev-1.13.0`; the expected Choice labels were returned for (A) a continuous usable cycleway, (B) no currently acceptable option after closure with no bypass, and (C) unknown due to insufficient evidence. ## Experiments required before authority-bearing use

- Build a frozen, claim-labeled corpus of connection and alignment cases, including unknown, stale, conflicting, adversarial and omitted-candidate states. Measure label accuracy and calibration separately for each claim and action.
- Test candidate coverage as a hard precondition: verify that the model can select `none`/`unknown` but cannot create a candidate absent from the compiler inventory.
- Test changed-state iteration and replay with pinned model IDs, question/profile versions and evidence fingerprints. A changed source observation must invalidate only the affected judgment records.
- Test exact-geometry guardrails independently: Jev outputs may recommend a supplied candidate or request review, while geometry libraries prove continuity, distance, intersection, route direction and topology.
- Compare staged deterministic passes with a complementary generative/reasoning model for decomposition and proposal drafting. Score whether the extra model improves reviewed decisions without bypassing evidence, policy or human authority.
- Define human and officer review for social, legal, equity, safety and deliverability claims. The TypeSafe sources reviewed here describe model judgments and routing uncertainty; they do not establish those public-interest conclusions.
