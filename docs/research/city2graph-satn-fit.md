# City2Graph fit for the SATN compiler

Research ticket: [Compare city2graph with SATN compiler architecture and contracts](https://github.com/awjreynolds/agentic-satn-compiler/issues/401). The upstream source was inspected at commit [`1fc5321770cdc4df4cf9cee21e3e41ff6e0e5cd2`](https://github.com/c2g-dev/city2graph/tree/1fc5321770cdc4df4cf9cee21e3e41ff6e0e5cd2).

## Decision

City2Graph should not become a SATN core dependency or replace `RoadGraph`, the lossless `PlanningGraph`, candidate discovery, or the compiler's evidence/selection contracts. It is a plausible bounded, optional analysis adapter: use it to prepare morphology, GTFS/GBFS, OD or proximity observations, then retain the resulting export as governed evidence. A separate experiment may benchmark its segment conversion or Rust-backed graph representation, but there is no evidence here that it improves authoritative route compilation.

## Capability and contract comparison

City2Graph's useful overlap is at the GeoPandas/graph interchange boundary. `segments_to_graph()` turns LineString endpoints into unique nodes and a directed or multigraph edge frame, preserving parallel edges when requested ([upstream `morphology.py`](https://github.com/c2g-dev/city2graph/blob/1fc5321770cdc4df4cf9cee21e3e41ff6e0e5cd2/city2graph/morphology.py#L1607-L1753)). Its `gdf_to_nx`/`nx_to_gdf` converters support homogeneous and typed heterogeneous frames, while `GraphMetadata` tracks CRS, directionality, multigraph and geometry reconstruction metadata ([`conversion.py`](https://github.com/c2g-dev/city2graph/blob/1fc5321770cdc4df4cf9cee21e3e41ff6e0e5cd2/city2graph/utils/conversion.py#L34-L159), [`base.py`](https://github.com/c2g-dev/city2graph/blob/1fc5321770cdc4df4cf9cee21e3e41ff6e0e5cd2/city2graph/base.py#L30-L148)).

The SATN seam is stricter: `PlanningGraphRequest` requires an explicit CRS, pinned source-export fingerprint and profile, while each `PlanningEdgeRecord` retains directed identity, geometry fingerprint, access facts, reciprocal state, components and observation IDs ([`planning_graph.py`](../../src/satn/planning_graph.py#L51-L136)). `build_planning_graph()` validates edges, preserves the source universe and fingerprints the snapshot ([`planning_graph.py`](../../src/satn/planning_graph.py#L217-L365)). City2Graph's graph metadata is useful transport, but does not provide SATN evidence observations, claim-specific unknown/conflict states, governed source licences, stable content identities, route controls, or compiler fingerprints.

City2Graph's morphology builder creates a different product: building-derived place tessellations plus movement segments and place/place, movement/movement and place/movement relations ([`morphology.py`](https://github.com/c2g-dev/city2graph/blob/1fc5321770cdc4df4cf9cee21e3e41ff6e0e5cd2/city2graph/morphology.py#L153-L172), [same file](https://github.com/c2g-dev/city2graph/blob/1fc5321770cdc4df4cf9cee21e3e41ff6e0e5cd2/city2graph/morphology.py#L277-L322)). That could inform urban permeability or access research, but SATN's urban contract deliberately emits governed spines, low-traffic areas and named portals from official classification/context ([`urban.py`](../../src/satn/urban.py#L67-L189)); a tessellation or centroid edge cannot author those semantics.

Its transportation module loads local GTFS into in-memory DuckDB and derives stop-to-stop OD legs, then a weighted travel-summary graph with service frequency and travel time ([`transportation.py`](https://github.com/c2g-dev/city2graph/blob/1fc5321770cdc4df4cf9cee21e3e41ff6e0e5cd2/city2graph/transportation.py#L511-L571), [same file](https://github.com/c2g-dev/city2graph/blob/1fc5321770cdc4df4cf9cee21e3e41ff6e0e5cd2/city2graph/transportation.py#L718-L753), [same file](https://github.com/c2g-dev/city2graph/blob/1fc5321770cdc4df4cf9cee21e3e41ff6e0e5cd2/city2graph/transportation.py#L1198-L1269)). Its OD API turns an adjacency matrix or weighted edge list plus zones into spatial graph frames ([`mobility.py`](https://github.com/c2g-dev/city2graph/blob/1fc5321770cdc4df4cf9cee21e3e41ff6e0e5cd2/city2graph/mobility.py#L54-L140)). These are relevant to a future demand/transit evidence pass, not to current SATN geometry: candidate discovery is finite and evidence-bound, and explicitly has no external routing provider or shortest-path authority ([`candidate_discovery.py`](../../src/satn/candidate_discovery.py#L1-L8), [`candidate_discovery.py`](../../src/satn/candidate_discovery.py#L791-L884)).

## Rustworkx, dependencies and governance

`rustworkx>=0.17.1` is a required City2Graph dependency, but the inspected implementation uses it for explicit NetworkX↔Rustworkx conversion (`nx_to_rx`/`rx_to_nx`), not as a SATN-compatible routing backend ([`pyproject.toml`](https://github.com/c2g-dev/city2graph/blob/1fc5321770cdc4df4cf9cee21e3e41ff6e0e5cd2/pyproject.toml#L25-L40), [`conversion.py`](https://github.com/c2g-dev/city2graph/blob/1fc5321770cdc4df4cf9cee21e3e41ff6e0e5cd2/city2graph/utils/conversion.py#L2176-L2242)). The core dependency set also adds DuckDB, libpysal, momepy, Overture Maps, SciPy and geopy; PyTorch/PyG are optional but materially expand the environment ([`pyproject.toml`](https://github.com/c2g-dev/city2graph/blob/1fc5321770cdc4df4cf9cee21e3e41ff6e0e5cd2/pyproject.toml#L25-L64)). SATN already has a pinned, narrower GeoPandas/Shapely/NetworkX stack ([`pyproject.toml`](../../pyproject.toml#L1-L44)). Adding City2Graph to the core would enlarge dependency and digest surface without a demonstrated authoritative benefit; ADR 0010 requires any active adapter to be registered, fingerprinted and tested as an explicit optional bundle ([`0010-configuration-sensitive-compilation-dependencies.md`](../../docs/adr/0010-configuration-sensitive-compilation-dependencies.md#L17-L63)).

City2Graph is BSD-3-Clause ([license](https://github.com/c2g-dev/city2graph/blob/1fc5321770cdc4df4cf9cee21e3e41ff6e0e5cd2/LICENSE#L1-L18)), compatible with SATN's MIT project licence ([`pyproject.toml`](../../pyproject.toml#L1-L8)). It declares 1.0.0/“Production/Stable” ([upstream metadata](https://github.com/c2g-dev/city2graph/blob/1fc5321770cdc4df4cf9cee21e3e41ff6e0e5cd2/pyproject.toml#L5-L24)) and has a 2026-07-31 first stable release with CI tests on Python 3.12–3.14 ([changelog](https://github.com/c2g-dev/city2graph/blob/1fc5321770cdc4df4cf9cee21e3e41ff6e0e5cd2/CHANGELOG.md#L24-L49), [workflow](https://github.com/c2g-dev/city2graph/blob/1fc5321770cdc4df4cf9cee21e3e41ff6e0e5cd2/.github/workflows/test.yml#L37-L72)). This is credible maintenance evidence, not evidence of semantic suitability or long-term governance alignment.

## Safe seam and smallest validation

The only justified seam is a private optional adapter after a pinned SATN export: feed selected routable/evidence frames to `segments_to_graph`, morphology, GTFS/OD or proximity analysis; return a typed observation bundle with engine version/commit, input hashes, CRS, parameters, licence and output hash. Do not let City2Graph emit route geometry, mutate `PlanningGraphSnapshot`, choose candidates, or publish. SATN's existing external-analysis port already requires frozen exports, explicit CRS/date/seed/thread policy and returns observations separate from geometry ([`external_analysis.py`](../../src/satn/external_analysis.py#L186-L334)); unavailable/invalid adapters must remain typed non-fatal outcomes ([`external_analysis.py`](../../src/satn/external_analysis.py#L799-L847)).

Smallest next validation: build one offline fixture adapter (no new core dependency) using the existing SATN planning-graph fixture and a tiny GTFS/OD or buildings/segments frame. Compare (1) endpoint/parallel-edge preservation, (2) CRS and stable-ID round-trip, (3) deterministic output hash across repeated runs, and (4) whether one observation changes an existing governed criterion without geometry or selection mutation. Add it only as an optional dependency bundle if that fixture demonstrates a decision-relevant observation and satisfies the manifest tests required by ADR 0010. Otherwise retain City2Graph as an external research tool.
